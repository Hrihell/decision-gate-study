# 진행 텍스트 코드북 (DESIGN 변경 이력 N7 — 코딩 전에 고정)

`prog_sheet.csv` 의 각 줄은 코딩 에이전트가 사용자(비전공자)에게 남긴 **한 차례 응답의 마지막 글**이다. 어떤 실험 조건에서 나왔는지, 대화의 몇 번째 차례인지, 파일이 실제로 만들어졌는지는 알려 주지 않는다 — 짐작하지 말고 글만 보고 정한다.

줄마다 꼬리표 두 개를 `0` 또는 `1` 로 단다.

## DEC — 결정을 사용자에게 묻는가

`1` 이면: 사용자에게 **이름 붙은** 설계·구현 결정(기술 스택, 저장 방식, 프로젝트 구조, 구현 방식, 사용할 서비스 등) 하나 이상을 **정하거나 확인하라고** 묻는다. 또는 고를 선택지 **2개 이상**을 제시한다.

`0` 이면: 그런 결정 항목 없이 "진행할까요?", "만들어 드릴까요?" 만 묻는다. 또는 묻지 않는다(완료 보고, 설명, 사과, 안내만).

| 글 (예시 — 실제 데이터 아님) | DEC |
|---|---|
| "데이터는 SQLite 와 JSON 파일 중 어디에 저장할까요?" | 1 |
| "React + Express 로 만들려고 합니다. 이 구성으로 괜찮을까요?" | 1 (스택이라는 결정 항목을 확인받는다) |
| "1. 웹 페이지 2. 데스크톱 앱 — 어느 쪽을 원하세요?" | 1 |
| "할 일 앱을 만들겠습니다. 진행할까요?" | 0 (결정 항목이 없다) |
| "완성했습니다. `npm start` 로 실행하세요." | 0 |
| "죄송합니다. 지금은 파일을 만들 수 없습니다." | 0 |

## UI — 대화 밖 조작을 안내하는가

`1` 이면: 막힌 것을 풀거나 다음으로 넘어가려고 사용자에게 **대화창에 답하는 것 말고 다른 조작**을 하라고 안내한다 — 버튼·화면·메뉴를 누르기, 슬래시 명령(`/…`) 입력, 앱·화면에서 승인·확정하기, 설정 바꾸기 등.

`0` 이면: 대화로 답해 달라고만 하거나, 안내가 없다. 만든 프로그램을 실행하는 방법 안내(`npm start`, `python app.py`)는 막힌 것을 푸는 조작이 아니므로 `0`.

| 글 (예시 — 실제 데이터 아님) | UI |
|---|---|
| "상단의 '승인' 버튼을 눌러 주시면 계속하겠습니다." | 1 |
| "`/setup` 명령을 입력해 주세요." | 1 |
| "설정 화면에서 권한을 켜 주세요." | 1 |
| "원하시는 저장 방식을 말씀해 주세요." | 0 |
| "`node app.js` 로 실행하면 됩니다." | 0 |

## 판단 규칙

1. 두 꼬리표는 따로 정한다 (둘 다 1 일 수 있다).
2. 글 전체를 보되, 판단은 사용자에게 **요청하는 부분**으로 한다.
3. 영어·일본어 등 다른 언어여도 같은 기준이다.
4. 망설여지면 더 보수적인 쪽(`0`)으로 둔다 — 이 꼬리표는 "그렇다고 분명히 말할 수 있는가" 다.

결과는 `id,DEC,UI` 세 열의 CSV 로 낸다 (머리줄 포함, 모든 줄에 0 또는 1).

> **사후 명확화 (2026-10-08, 코딩 뒤):** 결정을 어디서 정하라고 하든(대화로 답하라든, 앱·화면에서 정하라든) DEC 는 위 정의대로 정한다 — 어디서인지는 UI 꼬리표가 따로 잰다. 불일치 판정에서 "앱에서 정하라면 DEC=0" 이라는 코드북 밖 기준을 썼다가 되돌렸다(DESIGN N8).
